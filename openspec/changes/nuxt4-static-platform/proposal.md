## Why

The site was a single-chapter build: "Rio Grande Valley"/"RGV DSA" was baked into the theme's name and identifiers, copy defaults, artwork, seed content, feed metadata, and social URLs, so it could not be re-pointed at any other chapter without a code change. At the same time its front end is a hand-rolled Vue-islands-plus-custom-SPA layer inside the WordPress theme, which the front-end team wants to replace with a standard Nuxt 4 application that is generated statically and rebuilt on demand — without ever running `node` on the WordPress host, and with a process that stays seamless for visitors and editors.

## What Changes

- **Theme rename → Progress Now.** The theme directory, text domain, PHP prefix (`progressnow_*`), filter namespace (`progressnow/context/*`), REST namespace (`progressnow/v1`), block names (`progressnow/*`), ACF keys (`field_progressnow_*`), and options-page slug are renamed. `bin/scrub-brand.sh` migrates an existing database (block markup, ACF key references, theme mods, content-version option, active theme). **BREAKING** for anything that consumed the old REST namespace or block names.
- **Brand scrub.** Every reader-, crawler-, and editor-visible regional reference is gone from copy defaults (EN **and** ES — Spanish content stays, only regional mentions are rewritten), artwork, seed data, ICS `PRODID`/calendar name, the Polylang string group, `humans.txt`, theme metadata, share subjects, storage keys, and the ICS feed slug (`/feed/chapter-events/`; the old slugs 301). Chapter identity — name, short name, region label, hero headline, logos, hero photo, artwork, share image — lives in Chapter Settings → **Identity & brand** with neutral in-repo placeholders (simple SVG lockups/art; picsum.photos stock frames with generic filenames) that the chapter replaces without code. Socials and the newsletter have no default; their UI renders only when configured. The scrub script also rewrites existing database content and prints an audit.
- **Nuxt 4 static site (`nuxt-js/`).** The theme's `src/` Vue islands, Tailwind v4 theme, shadcn-vue library, zod contracts, and vitest suite move into a Nuxt 4 app that `nuxt generate`s the whole public site (both languages) from the theme's REST API. Route structure, URLs, EN/ES switching, blog search/filter/pagination, calendar, single post/event, a11y widget, view transitions, and every other current behavior are preserved (functional parity is a hard requirement; the front page stays visually close to the current build).
- **PHP-first handoff.** WordPress/Timber remains the first response for every public URL (crawlers, deep links, no-JS): Twig renders the SEO head (unchanged `inc/seo.php`), crawlable chrome and content, an embedded route payload, and the Nuxt client bundle resolved from a build manifest. On load the Nuxt app mounts in place of the shell (seeded from the embedded payload — no refetch, no visible swap) and all subsequent navigation happens inside the static Nuxt rendition using its prerendered `_payload.json` files, falling back to the REST API for dynamic interactions and whenever the shell is fresher than the static build. Logged-in users with the admin bar keep plain PHP page loads.
- **On-demand rebuild.** WordPress dispatches a rebuild (content-version bump, wp-admin button, or WP-CLI — coalesced and retried) through a pluggable transport: `github` (a `repository_dispatch` that runs the repo's `rebuild-site` workflow) or `webhook` (a signed HMAC POST to any receiver, e.g. an AWS endpoint). The workflow runs `nuxt generate` and deploys to a pluggable target (S3 sync with optional CloudFront invalidation, or rsync to the WordPress host). Completion is detected from the build's `shell-manifest.json` (plus an optional signed status callback), after which WordPress purges its page cache. No `node` process runs on the WordPress host. Infrastructure is **reference only**: a Terraform module and a deployment guide ship in the repo; nothing is provisioned by this change (the operator deploys).
- **Static asset serving without a CDN dependency.** The build's `/_nuxt/*`, `*/_payload.json`, and `/shell-manifest.json` are served on the site's own domain either from a directory on the WordPress host (default: web-server rewrite with a PHP passthrough fallback) or, optionally, from S3 behind CloudFront path behaviors.
- **BREAKING:** the theme's Vite bundle (`@kucrut/vite-for-wp`, `vite.config.js`, `dist/`), `src/` islands, and `src/ts/navigation.ts` are removed at cutover; the app does not render without a generated build at the configured static location. Default social/newsletter URLs no longer exist and must be set in Chapter Settings.

## Capabilities

### New Capabilities
- `chapter-neutral-branding`: no regional references anywhere visible; chapter identity, artwork, and socials are Chapter Settings data with neutral in-repo placeholders; rename + scrub database migration.
- `php-shell-handoff`: the PHP-rendered shell document contract (SEO head, crawlable content, embedded route payload, build-manifest asset tags, app root), seamless takeover, admin-bar bypass, and the static passthrough.
- `nuxt-static-site`: the Nuxt 4 application — route parity with WordPress permalinks in both languages, generation from the REST API, route manifest, payload seeding from the shell, freshness guard, `shell-manifest.json` emission, and functional parity with the current islands.
- `static-rebuild-pipeline`: WordPress-side trigger/coalesce/dispatch/status (hooks, wp-admin panel, WP-CLI) with `github` and signed `webhook` transports; the `rebuild-site` GitHub Actions workflow (generate + pluggable deploy target); completion detection and cache purge; reference Terraform + deployment guide.
- `static-asset-serving`: same-origin serving of the generated assets/payloads in same-host mode (default) or CDN mode (optional CloudFront + S3), with cache-control policy per path class.

### Modified Capabilities
- `front-page`: hero headline (text by default, optional artwork), hero photo, and who-we-are artwork come from Chapter Settings with neutral placeholders; front page is rendered as shell + Nuxt page.
- `site-chrome`: shared chapter context gains identity fields (name, short name, region label, logos) with neutral defaults and empty social/newsletter defaults; header/footer are server-rendered in the shell and re-rendered by the Nuxt app; mobile-toggle requirement no longer names the removed `src/ts` file.
- `island-data-fetch`: island-specific requirements are removed (islands no longer exist); the behaviors move to `nuxt-static-site` (archive/calendar fetching) and `php-shell-handoff` (crawlable fallbacks).
- `rest-api`: additive `/v1` endpoints — `/site`, `/routes`, `/front-page`, `/pages/{path}`, `/events/{slug}`, `/build-status` — `lang` accepted everywhere, and a `seo` block on every route payload.
- `contract-governance`: schema definition lives in the Nuxt app; fixtures stay theme-owned and are consumed by the app's vitest suite; new envelopes get fixtures.
- `internationalization`: language-neutral tokens come from Chapter Settings; registered strings live under the "Chapter" group and are delivered to the Nuxt app through the `/site` payload as well as rendered in Twig.
- `design-tokens`: brand artwork list is the neutral placeholder set with settings-driven overrides; the a11y persistence key is renamed with migration.

## Impact

- **Theme (`wp-content/themes/progressnow`)**: renamed from `rgvdsatheme`; new `inc/identity.php` (done), `inc/shell.php`, `inc/rebuild.php`; `inc/rest.php` extended; `inc/seo.php` refactored to serialize per-route SEO; copy defaults rewritten (done); `views/*.twig` slimmed to shell markup; `bin/seed.php` rewritten (done); new `bin/scrub-brand.sh` and `bin/worktree-bootstrap.sh` (done); `src/`, `dist/`, `vite.config.js`, `package.json`, npm deps removed at cutover; `composer.json` drops `kucrut/vite-for-wp`.
- **New `nuxt-js/`**: Nuxt 4 app (Vue 3.5, Tailwind v4, shadcn-vue, zod, vitest, eslint) — owned by the front-end team after the scaffold and data layer land.
- **New `.github/workflows/rebuild-site.yml`**, **`infra/terraform/`** (reference module, not applied), **`docs/deployment.md`** (operator guide).
- **CI**: `.github/workflows/ci.yml` path updated (done) and gains a `site` job (lint/typecheck/test/generate against fixtures); keeps the PHPUnit job.
- **Database**: one-time rename + scrub migration on existing installs (`bin/scrub-brand.sh`); new Chapter Settings fields; a `chapter_build_state` option.
- **Runtime/hosting**: no CDN required; WordPress needs outbound HTTPS to GitHub (or the webhook receiver) and a reliable cron tick (`DISABLE_WP_CRON` + system cron recommended). WP Super Cache purge hooks into build completion.
- **Coordination**: the pending `security-*` changes were mechanically renamed to the new identifiers; the CSP in `security-headers-and-cicd-gates` must allow the same-origin module script and JSON payload (no inline executable script is introduced); `security-rest-cache-dos-hardening` limits apply to the new endpoints. The empty `deploy-pipeline` change scaffold was removed as superseded.
