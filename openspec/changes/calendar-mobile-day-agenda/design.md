## Context

The calendar island exists three times. next-js (`components/site/calendar/*.tsx`) server-renders the requested month from props with the server's `todayISO`, owns URL state, and already has a `role="grid"` with a roving tabindex on the gridcell `div`. The theme's Vue islands (`src/components/site/*.vue`) mount client-side after the Twig "Upcoming events" first paint, compute today from `new Date()`, and have no keyboard grid. nuxt-js (`app/components/site/*.vue`) is a byte mirror of the theme Vue under `test/unit/shared-source-drift.test.ts`, mounted in `<ClientOnly>`. Labels flow one way: `progressnow_i18n_strings()` (`inc/i18n.php`) → Polylang → `/site` `strings` → next-js `calendarLabels()`, nuxt-js `RouteCalendar.vue` `labels`, Twig `calendar_props`; Spanish pairs are seeded by `bin/seed.php`. Under 700px (the grid's own `min-[700px]:` breakpoint, not `md`) the grid shows dots and a legend that points at the List view; List is a flat run of `EventCard` rows.

The visual source is `design_handoff_calendar_day_agenda/` (main checkout, untracked, deleted before the commit); the delta specs carry every value.

## Goals / Non-Goals

**Goals:** one tap from the compact grid to an event; a day-grouped List with past days folded away; the same DOM semantics, states and copy in all three renderers; every new string translatable with an English fallback; axe-clean at 390px; the ≥ 700px chip → dialog flow unchanged apart from where focus lands.

**Non-Goals:** persisting the selected day or the past toggle in the URL; localized month/weekday names (the English constants stay, as the month heading does today); the desktop grid design; `EventDetailDialog`; the Twig no-JS first paint; moving the Vue sources into a package (`single-source-shared-ui`).

## Decisions

- **One cell anatomy at every width: `role="gridcell"` div → day `<button>` → chips.** The button (numeral + dots, `aria-label` "Saturday, September 12, 2 events" / "…, no events" / "…, today", `aria-disabled` out of month so arrow navigation still crosses padding cells) fills the cell under 700px and is the numeral row above the chips from 700px; it carries the roving `tabIndex` and the key handler, so the grid stays one tab stop with arrows / Home / End / PageUp / PageDown. Enter / Space / click: under 700px select the day; at ≥ 700px open the event or focus the chips, as today. The focus ring stays on the whole cell through `has-[:focus-visible]:` on the gridcell. Rejected: a clickable div with `aria-selected` (no native activation for touch AT, not the "real button" the handoff asks for); two DOM branches per width (hydration churn, duplicated markup); wrapping the chips in the day button (nested interactive content).
- **`compact` is a runtime media flag, not markup.** `(max-width: 699.98px)` via `useSyncExternalStore` (server snapshot `false`) in React and `useMediaQuery` from `@vueuse/core` (already a dependency) in Vue. It gates only activation semantics and `aria-pressed`; dots, the agenda panel and the grouped list are rendered at every width and toggled by CSS, so SSR / no-JS first paint is width-agnostic. jsdom / happy-dom have no `matchMedia` → treated as desktop; tests stub it to opt into compact. Rejected: probing layout (`getClientRects`) at event time (hacky, untestable in jsdom); CSS-only (Enter must differ by width per the handoff).
- **Agenda panel always rendered, `min-[700px]:hidden`.** `role="region"` `aria-live="polite"`, named by `cal_day_region`; `display:none` at desktop means no stray announcements there. Selection state exists at every width and is simply invisible at ≥ 700px.
- **Selection is nullable state plus a derived default.** `selectedDay: string | null`; `agendaDay = selectedDay ?? defaultSelectedDay(cells, todayISO)`. Month change and category change set it back to `null`, so the default rule (today → first filtered event day → the 1st) re-applies against the new cells without an effect. `showPast` resets to `false` on month change only. Neither is URL state (`calendarHref` untouched). Rejected: `?day=` (changes the shareable URL shape and the server render for no navigation benefit).
- **Pure, twinned helpers.** next-js `lib/calendar.ts` gains `groupByDay(events, todayISO) → DayGroup[]` (`key, label, dow, num, isToday, isPast, events`), `defaultSelectedDay(cells, todayISO)`, `nextEventDay(days, afterKey)` (wraps), `dayHeading(iso)` ("Saturday, Sep 12"), `shortDate(iso)` ("Sep 8") and `formatLabel(template, vars)` (`{n}` / `{month}` / `{date}` substitution). The theme gets `src/lib/calendar.ts` holding the same helpers plus `monthCells` / `DayCell` extracted from `MonthGrid.vue` and `todayISO()` (`new Date()`, computed once per island mount); nuxt-js mirrors the file and the drift test lists it.
- **Agenda card is an `EventCard` variant.** `variant="agenda"` with a resolved `category` (`label`, `color`) and `past` flag; the caller resolves the category through `categoryById`. `data-variant` on the card keeps `event-card` the one testid. Rejected: a second card component (two recipes to drift; the tile row must survive for "More upcoming events" and the Twig first paint).
- **List grouping at every width; past = `key < todayISO`.** Groups from `groupByDay`; the sticky badge (`top:76px`, under the 60–68px sticky header) is `aria-hidden`, the `<h3>` carries the date. Past cards render at `opacity:.6` with every text line in `#1B1B22` — muted text at .6 over white composites to ≈ 2.9:1 and would fail the axe gate; ink composites to ≈ 4.52:1. The empty-month block, summary and toggle rules follow the spec.
- **Strings: flat keys, `{name}` placeholders, `_one` / `_other` plurals.** New `cal_*` slugs in `progressnow_i18n_strings()` (see the events-presentation delta), the four keys next-js already reads but the theme never registered (`cal_prev`, `cal_next`, `cal_loading`, `cal_retry`) added alongside, Spanish pairs in `bin/seed.php`, `tests/fixtures/site.json` regenerated by the PHPUnit fixture writer so the next-js / nuxt-js tests see the keys. No ICU: two keys per plural, `n === 1` picks `_one`. Rejected: hard-coded copy in the islands (the Vue legend is hard-coded today and is the thing being replaced).
- **Vue islands get the React grid's keyboard model.** `MonthGrid.vue` adopts the roving tabindex, the same key map, `emit("day-select", key)` and `emit("month-change", delta)` beside the existing `select`; `EventCalendar.vue` owns `selectedDay` / `showPast`, renders the agenda panel, and takes props for every new label plus prev / next / loading / retry (Twig `calendar_props` and nuxt `labels` supply them). nuxt-js is updated by copying; only `RouteCalendar.vue` is edited by hand.
- **Testids.** `month-grid-day` stays on the gridcell (+ `data-selected`); new `month-grid-day-button`, `day-agenda`, `day-agenda-heading`, `day-agenda-count`, `day-agenda-empty`, `day-agenda-jump`, `day-agenda-see-list`, `event-list-summary`, `event-list-past-toggle`, `event-list-day` (`data-date`, `data-past`, `data-today`), `event-list-day-badge`, `event-list-day-heading`; `event-card` gains `data-variant`.
- **Order of work.** Strings + fixture first (every renderer's tests read `site.json`), then next-js (the active build-out, its tests define the behavior), then the theme Vue with the same test cases in `@vue/test-utils`, then the nuxt mirror, then the demo snapshot.

## Risks / Trade-offs

- [Desktop focus target moves from the gridcell to the day button] → ring kept on the cell via `has-[:focus-visible]:`; existing component / e2e queries move from `getByRole("gridcell")` to `getByRole("button")`; `aria-current="date"` stays on the gridcell.
- [Pre-hydration semantics on a phone] → until `compact` flips after mount, `aria-pressed` is absent and Enter would open the dialog; a few ms, and no-JS users see the same inert dots as today.
- [Drift rule] → four `.vue` files plus `lib/calendar.ts` must stay byte-identical between theme and nuxt-js; `RouteCalendar.vue` differs by design.
- [English month names on `/es/`] → "9 eventos en September" mirrors the existing English month heading; tracked as a follow-up, not widened here.
- [Sticky badge under a taller header] → xl text size can grow the header past 76px and overlap the badge; decorative element, accepted.
- [Past-card contrast is near the 4.5:1 floor] → ink at .6 composites to ≈ 4.52:1; if the axe run reports it, raise past opacity to .65 (≈ 5.3:1) rather than exempting the rule.
- [Snapshot refresh needs the seeded Spanish strings] → run the seed's string pass on MAMP before `snapshot.mjs`; deploying from the worktree needs `vercel link` first and the pulled `.env.local` deleted afterwards.

## Migration Plan

No data or contract migration: the `strings` map only gains keys and every consumer falls back to English. Deploy in any order; the demo backend (mock-api) is redeployed before the app so the Vercel calendar shows the new copy. Rollback is a revert.
